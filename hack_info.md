# Meta Global AI Developer Hackathon - Participant Guide

> **Agent Summary:** Build a new project during Oct 27-Nov 4 using Meta's models. Submit a public repo + 3-minute demo video by Nov 4, 9:00 PM ET via the Cerebral Valley platform. Max team size: 4. Total prizes: $1,000,000.

## 1. Goal / Problem Statements

Your project **must** fit one of these tracks/statements:

### 1.1 Build for Your World
Bring Meta's models into your domain. Solve a problem you know firsthand, free up time and mental space, and make something possible that wasn't before.

### 1.2 Push the Frontier
Use Meta's models to tackle challenges in software, robotics, manufacturing, energy, materials, and beyond. Give a machine a new capability, accelerate a scientific experiment, or unlock a better way to understand and control a physical system.

### 1.3 Required Technology
Your project **must incorporate Meta's models**, including via:

**Meta Model API:**
- Muse Spark series
- Muse Wonder
- Muse Image
- Muse Voice
- Transcribe
- SAM 3.1

**Meta Open Weights Models:**
- Muse Glimmer
- Muse Spark Open

**Developer Tooling:**
- Muse Code (coding agent)

## 4. Rules

### MUST
- [ ] Repository must be **public / open source**
- [ ] Team size <= 4. Solo participants allowed.
- [ ] Build must be **new work created during the Hackathon**
- [ ] Clearly identify what was built during the Hackathon in demo and submission
- [ ] Use Meta Model API and/or Meta open-weight models
- [ ] Startups may build on existing products/codebases, but **must clearly identify new work**

### MUST NOT
- Violate legal, ethical, or platform policies
- Use code, data, or assets you do not have rights to
- Demo features/code/functionality not built during the Hackathon

> **Warning:** Failure to clearly identify original contributions will result in immediate disqualification at judges' sole discretion.

### 4.1 Anti-Projects (Avoid Building)
Do NOT build generic or banned projects, including:

- AI to generate/give medical advice (e.g., AI Mental Health Advisor, skin blemish detector)
- Basic RAG applications
- Simple Image Analyzers
- Simple "AI for Education" chatbots
- AI Job Application Screener
- AI Nutrition Coach
- Personality Analyzers
- Sports analyzers or coaches
- Anything political or involving war

*Note: This list is not exhaustive.*

## 8. Judging Process

### Stage 1: Pass/Fail
Determines baseline viability: Does the project fit the theme and reasonably use Meta Model API and/or Meta open-weight models built during the Hackathon?

### Stage 2: Scored Evaluation (0-10 scale)
| Category | Weight | Description |
| :--- | :--- | :--- |
| **Impact** | 30% | Real-world potential. Who benefits and how much? Could this become something people use? Fits problem statement? |
| **Use of Meta AI Tooling** | 25% | Creative use of Meta tooling. Beyond basic integration? Surprising capabilities? |
| **Technical Depth & Execution** | 20% | Sound, thoughtfully refined engineering. Real craft. |
| **Demo** | 25% | Working, impressive demo. Holds up live? Video is compelling to watch? |

### Stage 3: Final Round
Top 5 projects per track advance. Judges watch video demos live and rank using the same rubric.

## submission notes
1. The submission form takes one public GitHub repo URL, so a single monorepo is the safer choice. Cross-linking two repos from the main README is not guaranteed to be judged, since judges work from the one submitted repo and its setup instructions, so merge them into one repo.

2. The organizer answers don't say which keys judges must supply. What's confirmed is that the project has to run from the public repo's setup instructions, that judges may test with their own keys, and that API keys must never be committed. Explain in the README exactly which variables are needed for each mode (for example, `.env.example` lists `META_MODEL_API_KEY` and `BASETEN_API_KEY`, and which one is optional), and keep your replay mode in the README too. Baseten's hackathon key works only with `meta-models/muse-spark-open-1026`.

3. Judges can run the project from the repo's setup instructions without signing up for outside accounts, and a local setup with seed data or a mock-data path is acceptable. So a fallback that runs without MongoDB or a Telegram bot is in line with that, as long as the README documents it and the video shows the working flow with live Meta model calls visible.
